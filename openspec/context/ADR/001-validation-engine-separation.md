# ADR-001: Чистый компонент проверки правил

Дата пересмотра: 2026-11-08. Статус: принято для следующей реализации.

## Основание

Задание требует отделить логику правил от API и доступа к данным.
Для этого достаточно небольшого Java-компонента, а не отдельного сервиса.

## Решение

Сервис получает данные из репозиториев и передаёт immutable records в ValidationContext.
Контекст содержит подразделения, цели (включая родителей) и КР.
Движок проверяет только ACTIVE цели четырьмя выбранными правилами.
Каждое правило возвращает найденные нарушения как чистые данные:
rule_code, goal_id, severity. ID записи и run_id присваивает слой сохранения.

Правила не зависят от Spring, JPA, SQL и HTTP.
Результаты правил не являются JPA Entity.
Движок не считает дельту и не записывает историю.
Метрики и сравнение множеств также реализуются чистыми Java-функциями,
а сервис отвечает за подготовку данных и транзакции.

## Ограничение сложности

Можно явно собрать список четырёх правил в конфигурации приложения.
Динамическое обнаружение плагинов, отдельный rule server, DSL
и новый framework для этого не нужны.
