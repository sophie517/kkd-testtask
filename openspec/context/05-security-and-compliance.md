# Данные и безопасность

Обновлено: 2026-11-08.

Задание не требует авторизации, разграничения ролей, шифрования полей
или интеграции с корпоративным каталогом. В тестовом решении их не добавляем.
Перечень пользователей в бизнес-кейсе не означает необходимость реализовать RBAC.

owner_id — идентификатор сотрудника; он может быть связан с персональными данными
во внешней системе. Не называем его заведомо неперсональными данными.
Для демо используем вымышленные ID, не загружаем ФИО, email и реальные данные сотрудников.
Историческим снимкам owner_id не нужен: сохраняются только данные для метрик и API.

Пароль БД поступает из окружения; .env не коммитится.
.env.example содержит обозначенное демонстрационное значение, не рабочий секрет.
Секреты, owner_id, полные тела запросов и ответов не логируем.
Для диагностики достаточно ID прогона, кода правила, количества проблем и технической ошибки.

SQL-параметры передаём через параметры JPA/SQL, не конкатенацией ввода.
Ответ ошибки не раскрывает SQL, stack trace, внутренние пути и пароль.
Отсутствие авторизации — ограничение демонстрационного решения;
публикация в Интернет и инфраструктура HTTPS в эту задачу не входят.
