# 05 — Security and Compliance

## Классификация данных

| Тип данных | Пример | Хранится в v1? |
|---|---|---|
| Идентификаторы сотрудников | `owner_id` | Да (только ID, не ФИО) |
| Организационные данные | Подразделения, цели, КР | Да |
| Персональные данные (ФИО, email, телефон) | — | **Нет** |
| Чувствительные данные (пароли, токены, Base64) | — | **Нет** |

## Требования безопасности

- **Шифрование персональных данных** — не требуется (Pv1 не хранятся).
- **Аутентификация / авторизация** — не реализуются в v1.
- **Переменные окружения** — секреты и пароли хранятся только в переменных окружения, не в коде.
- **`.env.example`** — обязателен, без реальных паролей.

## Ограничения логирования

| Запрещено | Почему |
|---|---|
| ФИО, email, телефоны | Персональные данные |
| `owner_id` | Идентификатор сотрудника |
| Пароли, токены | Секреты |
| Полные тела HTTP-запросов/ответов | Содержат чувствительные данные |
| Base64, фотографии | Чувствительные данные |

| Разрешено для диагностики | Пример |
|---|---|
| `run_id` | `RUN-008` |
| Коды правил | `GOAL_NO_OWNER` |
| Количество нарушений | `23 issues found` |
| Технические ошибки | `Failed to connect to PostgreSQL` |

## Безопасность API

- Spring Data JPA использует параметризованные запросы (защита от SQL-инъекций).
- SQL-запросы не формируются конкатенацией пользовательского ввода.
- Предполагается работа за reverse proxy с HTTPS.
