# KKD Service — начало работы

Обновлено: 2026-11-08.

Сервис на Java проверяет качество целей и ключевых результатов в PostgreSQL,
сохраняет результаты и отдаёт REST API для страницы ККД.

## Источник требований

1. [Исходное задание](_raw/business-assignment.md) — главный источник требований.
2. Эти контекстные файлы — выбранный простой вариант решения и уточнения пробелов.
3. Новые планы изменений и код должны соответствовать заданию и этому контексту.

Если код расходится с заданием, это не основание менять требования под код.
Числа в примере JSON исходного задания иллюстрируют форму ответа, но не являются
согласованным тестовым набором: в исходном примере счётчики противоречат друг другу.
Сам исходный текст не редактируем. Проверенные примеры находятся в examples/README.md.

## Текущее состояние

Все семь этапов реализованы и проверены. Полный clean verify с настоящей PostgreSQL:
62 теста, 0 ошибок и пропусков. Проверены два чистых Docker-стенда, повторный старт,
реальный HTTP, ограничения и каскады, атомарность RunService, REPEATABLE_READ
и полный Liquibase update → rollback → update. Результаты —
[матрица приёмки](../../docs/verification.md), команды — [README](../../README.md).
Шесть основных capability синхронизированы в openspec/specs.
История этапов и архивов — в [карте](08-delivery-stages.md) и AI-PLAN.md.
Новая функциональность требует отдельного согласованного change.

Для обязательного артефакта работы с ИИ выбран [AI-PLAN.md](../../AI-PLAN.md).
Не нужно параллельно поддерживать ещё одну копию требований в корневой specs/.
