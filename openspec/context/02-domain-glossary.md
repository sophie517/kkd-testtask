# 02 — Domain Glossary

## Основные сущности

| Термин | Описание |
|---|---|
| **Unit** (Подразделение) | Иерархическая единица организации. Связь через `parent_unit_id`. Метрика подразделения включает дочерние подразделения автоматически. |
| **Goal** (Цель) | Единица OKR с `owner_id`, статусом, сроком, подразделением и возможной родительской целью. |
| **KeyResult** (Ключевой результат) | Привязан к цели. Содержит целевое и фактическое значение, вес (Integer, 2 знака после запятой), дату обновления факта. |
| **Run** (Прогон) | Моментальный снимок (snapshot) результатов проверки. Содержит `snapshot_date` и ссылку на предыдущий прогон для сравнения. |
| **Issue** (Проблема) | Нарушение правила, найденное в конкретном прогоне. Идентифицируется парой `rule_code + object_id`. |
| **Rule** (Правило) | Правило проверки с кодом и уровнем критичности (critical / major). Метаданные (code, description, severity) хранятся в БД (`kkd_rule`). Исполняемая логика — в Java (4 чистых класса + интерфейс + движок). |

## Статусы

| Статус | Описание |
|---|---|
| `ACTIVE` | Активная цель, по которой применяются все правила проверки. |
| `ARCHIVED` | Архивная цель, не проверяется. |

## Правила проверки

| Код | Описание | Важность | Применяется к |
|---|---|---|---|
| `GOAL_NO_OWNER` | Цель без ответственного (`owner_id` — null) | critical | Активные цели |
| `GOAL_NO_KR` | У активной цели нет ни одного ключевого результата | critical | Активные цели |
| `KR_WEIGHTS_SUM` | Сумма весов КР цели ≠ 100 | major | Активные цели с КР |
| `CASCADE_NO_PARENT` | Цель не связана с целью вышестоящего уровня | major | Активные цели (не корневого подразделения) |

## Бизнес-правила

- **CASCADE_NO_PARENT:** Родительская цель — цель из непосредственного родительского подразделения. Цели корневого подразделения освобождены от этого требования.
- **KR_WEIGHTS_SUM:** Используется `Integer` (не float/double). Сумма должна строго равняться 100. Значение 99.99 — нарушение.
- **GOAL_NO_KR vs KR_WEIGHTS_SUM:** Если у цели нет КР, регистрируется только `GOAL_NO_KR`. Дублирующее нарушение `KR_WEIGHTS_SUM` не создаётся.
- **Owner:** `owner_id` — ссылка на сотрудника (nullable). Хранятся только ID, не персональные данные.
- **Delta:** Идентичность нарушения — пара `rule_code + object_id`. Три сценария: `new` (только в текущем), `persisting` (в обоих), `resolved` (только в предыдущем).

## Решения v1

> Ниже — архитектурные и бизнес-решения, принятые на основе задания. Не являются требованиями.

| Решение | Обоснование |
|---|---|
| `KR_WEIGHTS_SUM` — вес типа `Integer` (не `float`/`double`) | Прямое требование задания: «Используется Integer». Избегание проблем с плавающей точкой. |
| `CASCADE_NO_PARENT` — родительская цель из непосредственного родительского подразделения | Интерпретация задания. Цели корневого подразделения освобождены от этого требования. |
| Правила проверяются только к активным целям | Задание: «применяются только к активным целям и их ключевым результатам». |
| Метаданные правил в БД, логика в Java | Задание требует «справочник правил» как таблицу БД. Логика правил — чистый Java-компонент. |
