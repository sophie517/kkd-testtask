# 01 — Product Context

## Назначение

KKD Service — сервис контроля качества данных по целям и ключевым результатам (OKR).
Сервис проверяет полноту и корректность заполнения целей, ключевых результатов
и предоставляет метрики качества для руководителей подразделений.

## Пользователи

| Роль | Описание |
|---|---|
| **Руководитель подразделения** | Основной пользователь. Запускает прогон проверок, анализирует метрики качества данных в своём подразделении и дочерних подразделениях. |

> **Non-goal v1:** Сотрудники не работают с системой напрямую. Аутентификация и авторизация не входят в scope первой версии. Роль администратора для управления справочниками не реализуется.

## Сценарии использования

### 1. Запуск прогона
Руководитель вручную инициирует прогон проверок для всего дерева подразделений.
Сервис применяет 4 правила проверки к активным целям и ключевым результатам,
сохраняет результаты и рассчитывает дельту с предыдущим прогоном.

### 2. Просмотр метрик
Руководитель запрашивает сводку по подразделению (включая дочерние):
- доля корректных целей
- количество активных целей
- количество целей с проблемами
- разбивка проблем по важности (critical / major)
- дельта: новые, сохраняющиеся, устранённые проблемы

### 3. Просмотр проблем
Руководитель фильтрует проблемы по подразделению, правилу и важности
с пагинацией (`limit`, `offset`, `total`).

## Метрики

| Ключ | Описание | Единица |
|---|---|---|
| `clean_goals_share` | Доля корректных целей (без нарушений) | % |
| `active_goals_count` | Количество активных целей | count |
| `goals_with_issues_count` | Количество целей с хотя бы одним нарушением | count |

Формат метрики: `key`, `title`, `unit`, `value`, `previous`, `delta`, `trend` (better / worse / neutral).

## Инварианты

1. Прогон запускается **вручную**, **для всего дерева подразделений**.
2. Метрика подразделения **всегда включает дочерние подразделения**.
3. Для **первого прогона** `compared_to`, `previous` и `delta` равны `null`.
4. Идентичность нарушения определяется парой `rule_code + object_id`.
5. Все правила применяются **только к активным целям** и их ключевым результатам.
6. `KR_WEIGHTS_SUM` — сумма весов КР должна строго равняться 100 (Integer, 2 знака после запятой).
7. Если у цели нет КР, регистрируется только `GOAL_NO_KR`, не создаётся дублирующее нарушение `KR_WEIGHTS_SUM`.

## Ограничения

- **Масштаб данных:** тестовый набор — 20–30 целей, 2–3 подразделения. Промышленные показатели производительности не определены.
- **Одна организация** — одно иерархическое дерево подразделений. Мульти-тенантность не входит в v1.
- **Без аутентификации** — в v1 не реализуется.
- **История прогонов обязательна** — каждый прогон сохраняется, сравнение с предыдущим.
