# 07 — Anti-Patterns

## Validation Engine

| Anti-pattern | Предпочтительная альтернатива |
|---|---|
| Обращение к БД из правила | Правило получает подготовленные данные через `ValidationContext` |
| Spring-аннотации в правилах (`@Component`, `@Autowired`) | Чистый Java-класс без зависимостей от Spring |
| Создание SQL-запросов внутри правил | Данные передаются из Service Layer |

## Слои

| Anti-pattern | Предпочтительная альтернатива |
|---|---|
| Контроллер обращается к репозиторию напрямую | Контроллер → Service → Repository |
| Дублирование логики расчёта метрик между контроллером и сервисом | Расчёт в сервисе, контроллер только возвращает DTO |
| Сравнение прогонов внутри Validation Engine | Сравнение в Service Layer |

## Сущности и DTO

| Anti-pattern | Предпочтительная альтернатива |
|---|---|
| Использование JPA Entity напрямую как DTO в API | Создание отдельных DTO классов |
| Маппинг Entity → DTO вручную в каждом месте | Использование mapper-утилиты или конструктора |

## Общие запреты

| Запрещено | Почему |
|---|---|
| `e.printStackTrace()` | Использовать логгер (`logger.error(...)`) |
| `System.out.println()` | Использовать логгер |
| `@Transactional` на контроллерах | Транзакции — в Service Layer |
| `@ComponentScan` с широкими пакетами | Явные зависимости, предсказуемая инициализация |
| Конкатенация строк для SQL-запросов | Parameterized queries через Spring Data JPA |
| Логирование чувствительных данных | ФИО, email, токены, полные тела запросов |

## Предпочтительные подходы

- **Dependency Injection** через конструктор (не через поле).
- **Immutable DTO** — record или final класс с приватным setter.
- **Чистые функции** в Validation Engine — входные данные → результат без side-effects.
- **Осмысленные имена** — `GoalWithoutOwner` вместо `Goal1`, `calculateDelta` вместо `process`.
