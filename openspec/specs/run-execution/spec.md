# run-execution Specification

## Purpose

Движок умеет находить проблемы, но нужен полный путь чтения исходных данных и атомарной записи результата. Прогон должен оставлять самостоятельную историю без частичных записей.

## Requirements

### Requirement: Проверка всего дерева

Сервис SHALL запускать выбранные правила для согласованного набора данных всей организации и фиксировать дату снимка.

#### Scenario: Успешный запуск
- **WHEN** внутреннему сервису переданы дата и корректное дерево исходных данных
- **THEN** создаётся новый завершённый прогон с результатом четырёх правил

#### Scenario: Некорректная иерархия
- **WHEN** в исходной иерархии найден цикл или несколько корней
- **THEN** запуск отклоняется без сохранения частичного прогона

### Requirement: Явная связь сравнения

Прогон SHALL хранить переданный идентификатор существующего предшественника либо null для прогона без сравнения.

#### Scenario: Первый прогон
- **WHEN** previousRunId отсутствует
- **THEN** сохраняется previous_run_id = null

#### Scenario: Последующий прогон
- **WHEN** передан ID существующего завершённого прогона
- **THEN** новый прогон ссылается именно на него

#### Scenario: Неизвестный предшественник
- **WHEN** передан неизвестный previousRunId
- **THEN** новый прогон не создаётся

### Requirement: Атомарный снимок

Система SHALL сохранять прогон, иерархию, все активные цели и проблемы как единый неизменяемый результат.

#### Scenario: Ошибка записи
- **WHEN** сохранение одного из результатов завершается ошибкой
- **THEN** ни прогон, ни его частичные дочерние записи не остаются в БД

#### Scenario: Изменения после проверки
- **WHEN** текущая цель архивируется и запускается новая проверка
- **THEN** снимок предыдущего прогона не изменяется

#### Scenario: Повторный старт приложения
- **WHEN** приложение перезапускается без явного вызова запуска
- **THEN** новый прогон не создаётся
