# quality-summary Specification

## Purpose

Сохранённые прогоны должны давать готовые показатели качества и динамику без расчётов на фронтенде. Расчёт обязан учитывать дочерние подразделения и собственную историю каждого снимка.

## Requirements

### Requirement: Сводка исторического поддерева

Сводка SHALL учитывать активные цели и проблемы выбранного подразделения вместе с потомками из снимка соответствующего прогона.

#### Scenario: Дочерние подразделения
- **WHEN** сводка запрошена для корня с двумя дочерними подразделениями
- **THEN** учитываются данные корня и обоих потомков без данных вне поддерева

#### Scenario: Текущие данные изменились
- **WHEN** после прогона структура текущих подразделений изменена
- **THEN** историческая сводка остаётся неизменной

### Requirement: Три показателя качества

Сводка SHALL возвращать долю корректных целей, число целей с проблемами и число проблем с текущими значениями и определённым направлением улучшения.

#### Scenario: Несколько нарушений цели
- **WHEN** одна из двадцати целей имеет два нарушения
- **THEN** число проблем увеличивается на два, число проблемных целей — на один

#### Scenario: Пустой набор
- **WHEN** в поддереве нет активных целей
- **THEN** все три значения равны нулю, доля представлена как 0.0

#### Scenario: Улучшение
- **WHEN** доля корректных целей растёт или количество проблемных целей/проблем снижается
- **THEN** trend соответствующей метрики равен better

### Requirement: Идентичность и дельта проблем

Система SHALL сравнивать проблемы по rule_code и goal_id и возвращать числа new, persisting, resolved.

#### Scenario: Три категории
- **WHEN** среди двух наборов есть уникальные текущие, общие и уникальные прошлые ключи
- **THEN** дельта содержит размеры разностей и пересечения; current=new+persisting и previous=resolved+persisting

#### Scenario: Перенос цели
- **WHEN** цель с тем же нарушением перемещена из одного поддерева в другое
- **THEN** для старого поддерева нарушение resolved, для нового new

#### Scenario: Новый ID записи
- **WHEN** один ключ присутствует в обоих прогонах с разными issue.id
- **THEN** проблема считается persisting

### Requirement: Отсутствие сравнения

Сводка SHALL возвращать null для недоступных предыдущих значений и дельты, не заменяя их нулями.

#### Scenario: Первый прогон
- **WHEN** предыдущего прогона нет
- **THEN** compared_to и весь delta равны null, previous/delta/trend метрик и previous/delta severity равны null

#### Scenario: Новое подразделение
- **WHEN** в выбранном снимке unit есть, а в предыдущем отсутствует
- **THEN** compared_to указывает предыдущий прогон, но все значения сравнения равны null

### Requirement: Разбивка по важности

Сводка SHALL всегда возвращать critical, major, minor в указанном порядке с суммой current, равной числу проблем.

#### Scenario: Нет minor-проблем
- **WHEN** сводка содержит только проблемы четырёх выбранных правил
- **THEN** строка minor присутствует с current=0, и сумма всех строк совпадает с issues_count
