# kkd-api Specification

## Purpose

Фронтенду необходимы три стабильных endpoint, отдающих готовые результаты. API должен обеспечить исторические фильтры, пагинацию и единый формат ошибок.

## Requirements

### Requirement: Список прогонов

GET /api/runs SHALL возвращать массив прогонов с id, status, snapshot_date, compared_to_run_id и общим issue_count.

#### Scenario: Два демо-прогона
- **WHEN** запрошен список прогонов после загрузки демо
- **THEN** возвращаются два COMPLETED-прогона, первый хронологически имеет compared_to_run_id=null

#### Scenario: Пустая история
- **WHEN** в БД нет прогонов
- **THEN** возвращается HTTP 200 и []

### Requirement: Сводка подразделения

GET /api/kkd/summary SHALL возвращать run, compared_to, unit, три metrics, issues_by_severity и delta по выбранному снимку.

#### Scenario: Успешная сводка
- **WHEN** переданы существующие run_id и unit_id
- **THEN** возвращается HTTP 200 с историческим названием подразделения и готовыми метриками

#### Scenario: Первый прогон в JSON
- **WHEN** запрошена сводка прогона без сравнения
- **THEN** поля сравнений присутствуют со значением null, а не пропущены и не заменены нулями

### Requirement: Список проблем с фильтрами

GET /api/kkd/issues SHALL фильтровать проблемы выбранного прогона по поддереву подразделения, коду правила и важности до пагинации.

#### Scenario: Совместные фильтры
- **WHEN** заданы unit_id, rule_code и severity
- **THEN** возвращаются только записи, удовлетворяющие всем фильтрам

#### Scenario: Допустимый minor
- **WHEN** задан фильтр severity=minor для выбранных четырёх правил
- **THEN** возвращается HTTP 200, items=[] и total=0

### Requirement: Стабильная пагинация

Список проблем SHALL содержать items,total,limit,offset и стабильную сортировку rule_code ASC, goal_id ASC.

#### Scenario: Значения по умолчанию
- **WHEN** limit и offset не переданы
- **THEN** используются limit=20,offset=0, total вычисляется до среза

#### Scenario: За концом списка
- **WHEN** корректный offset больше числа отфильтрованных проблем
- **THEN** возвращается пустой items и прежний total

### Requirement: Единый формат ошибок

API SHALL возвращать ошибку как объект error с code и message; неизвестный прогон/подразделение даёт 404, некорректные параметры — 422.

#### Scenario: Неизвестный прогон
- **WHEN** передан корректно оформленный несуществующий run_id
- **THEN** возвращаются HTTP 404 и RUN_NOT_FOUND

#### Scenario: Неизвестное подразделение
- **WHEN** run существует, но unit отсутствует в его снимке
- **THEN** возвращаются HTTP 404 и UNIT_NOT_FOUND

#### Scenario: Некорректный параметр
- **WHEN** обязательный параметр отсутствует/blank, фильтр неизвестен, число некорректно или limit/offset вне диапазона
- **THEN** возвращаются HTTP 422 и INVALID_PARAMS в едином формате

#### Scenario: Повтор параметра
- **WHEN** один скалярный параметр передан несколько раз
- **THEN** возвращаются HTTP 422 и INVALID_PARAMS
