## Goals / Non-Goals

**Goals:** обеспечить проверяемый результат этапа без зависимостей от реализации будущих этапов.
Ниже описаны выбранные проектные решения; их детали не приписываются исходному заданию.

**Non-Goals:** не создавать универсальную инфраструктуру или новые архитектурные слои,
не выполнять работу соседнего change; границы перечислены в proposal.md.


## Decisions

### 1. Расчёт в памяти

Для 24 целей загружаем снимки и строим поддеревья/множества в Java. Формулы задаёт 01-product-context.md, не дублируем их отдельной SQL-реализацией.

Альтернатива — сложные CTE и кеш — усложняет проверку при маленьком наборе.

### 2. Три метрики

clean_goals_share = (N-B)*100/N, goals_with_issues_count = B, issues_count = I. B считается по distinct goal_id. При N=0 доля 0.0; HALF_UP до одного знака. delta доли из округлённых значений в процентных пунктах.

Альтернатива — active_goals_count как метрика качества — не имеет однозначного better/worse.

### 3. Сравнение множеств

Сначала отобрать проблемы каждого снимка по его собственному поддереву, затем разности и пересечение по (rule_code,goal_id). issue.id и severity не входят в идентичность.

Альтернатива — JOIN по issue.id или сегодняшняя структура дерева — даёт ложные новые/исправленные проблемы.

### 4. Отсутствующая история

При previous_run_id=null compared_to=null; previous/delta/trend=null, весь delta=null. Если подразделения нет в прошлом, compared_to остаётся, остальные значения сравнения null. Пустое существующее поддерево считается нулевыми данными, не отсутствием истории.

Альтернатива — подставлять нули — показывает вымышленное улучшение или ухудшение.

### 5. Прикладные ошибки

Сервис сообщает отсутствие run/unit типизированными исключениями без HTTP-зависимостей; перевод в 404 выполняет этап 6. Название unit берётся из run_unit.

Альтернатива — ResponseEntity в сервисе — связывает расчёт с API.

## Risks / Trade-offs

- Несколько проблем одной цели завышают B → использовать множество goal_id.
- Перенос цели выглядит как исчезновение/появление проблемы подразделения → явно документировать такую семантику.
- Округление скрывает малую разницу → trend определяется по отображаемой delta, при нуле neutral.
