## Goals / Non-Goals

**Goals:** обеспечить проверяемый результат этапа без зависимостей от реализации будущих этапов.
Ниже описаны выбранные проектные решения; их детали не приписываются исходному заданию.

**Non-Goals:** не создавать универсальную инфраструктуру или новые архитектурные слои,
не выполнять работу соседнего change; границы перечислены в proposal.md.


## Decisions

### 1. Тонкие контроллеры

Контроллер проверяет/принимает параметры, вызывает сервис и маппит результат в DTO. Запросы данных и фильтрация живут в сервисах; прямого обращения к repository нет.

Альтернатива — вся логика в endpoint — дублирует расчёт и затрудняет тестирование.

### 2. Фильтрация и пагинация

Для небольшого набора достаточно отфильтровать problems по run/unit-поддереву/rule/severity, отсортировать rule_code ASC, goal_id ASC, затем взять срез. total вычисляется до среза. limit 1..100 default20, offset>=0 default0; защитить offset+limit от переполнения.

Альтернатива — сложный query-builder — не требуется при объёме задания.

### 3. Параметры и ошибки

run_id/unit_id строковые, max100 символов и не blank; отсутствующий optional означает отсутствие фильтра, переданный blank — 422. Несколько значений одного скалярного параметра отклоняются 422. Порядок: формат → существование run → unit. Невыбранный код правила — 422; minor допустим.

Альтернатива — позволить стандартному Spring вернуть 400 — расходится с заданием.

### 4. JSON

Отдельные records DTO со snake_case именами через явные JSON-аннотации или настройку только DTO. Даты ISO YYYY-MM-DD, null не исключаем. Статус COMPLETED, severity/trend — согласованные регистры.

Альтернатива — глобальный NON_NULL — ломает первый прогон.

### 5. Проверка HTTP-контракта

MockMvc без реального HTTP-сервера проверяет статусы и JSON. Не требуется Testcontainers; сценарии данных можно подставить через прикладные сервисы.

Альтернатива — только unit-тест mapper — не ловит стандартные ошибки binding Spring.

## Risks / Trade-offs

- Большой offset и переполнение → сначала проверить диапазон, вычислять границы безопасно и возвращать пустую страницу.
- Jackson может удалить null → отдельно проверить наличие полей первого прогона.
- Глобальный handler может маскировать 404/422 под 500 → проверять иерархию обработчиков.

## Migration Plan

Схема не меняется. Добавить контроллеры и DTO поверх готовых сервисов, проверить MockMvc и запросы к демо. Обновить README с curl и JSON; никаких POST endpoint.
