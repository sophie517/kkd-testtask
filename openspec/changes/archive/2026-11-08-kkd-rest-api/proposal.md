# Proposal

> Итог 2026-11-08: все задачи выполнены. Ранее перенесённые проверки
> завершены на финальной приёмке (62 теста, два Docker-стенда, HTTP,
> PostgreSQL и полный Liquibase rollback/update). Подробности — docs/verification.md.
> Описания переноса ниже сохраняют историю промежуточных этапов.


## Why

Фронтенду необходимы три стабильных endpoint, отдающих готовые результаты. API должен обеспечить исторические фильтры, пагинацию и единый формат ошибок.

## What Changes

- Создать контроллеры, отдельные response DTO и три GET endpoint.
- Добавить прикладные сервисы списка прогонов и проблем, исторические фильтры и пагинацию.
- Перевести ошибки в 404/422 и единый JSON, проверить null и snake_case.

## Scope

Только этап 6 — «REST API и ошибки». Этап 5 принят, прикладная сводка вычисляется по снимкам. Сервис запуска этапа 4 остаётся внутренним.
Зависимости реализации: `kkd-metrics-and-delta`.
Контекст этапа: [06-kkd-rest-api.md](../../../context/stages/06-kkd-rest-api.md).

## Non-goals

- Публичный запуск прогона, изменение целей, авторизация, frontend.
- Дублирование вычислений в контроллере и возвращение JPA Entity.
- Обязательная сеть в тестах; достаточно MockMvc без сервера.

## Capabilities

### New Capabilities

- `kkd-api`: REST API и ошибки; требования и сценарии этого этапа.

### Modified Capabilities

Нет. На момент планирования основных capability ещё нет; этап вводит собственную границу поведения.

## Impact

Будущие изменения: api/controller, api/dto, api/exception и прикладные query-сервисы. Схема не меняется; зависимости Spring Web уже подключены.
Решения, отсутствующие в исходном задании, являются проектными уточнениями и перечислены в design.md.

## Review status

Реализовано. HTTP-контракт проверен MockMvc; реальный сервер и БД не запускались.
Этот proposal не разрешает автоматически выполнять следующий этап.
