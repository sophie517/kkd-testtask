# Spec Delta

## Purpose

Нужна исполняемая проверка данных независимо от Spring и PostgreSQL. Она также должна подтвердить, что подготовленные демо-проблемы действительно следуют из выбранных правил.

## ADDED Requirements

### Requirement: Обособленная проверка

Компонент SHALL принимать подготовленные данные и возвращать найденные проблемы без обращения к API или хранилищу.

#### Scenario: Проверка обычным Java-вызовом
- **WHEN** компонент вызывается на наборе входных данных без запущенного приложения и БД
- **THEN** возвращается список нарушений с кодом, объектом и важностью

#### Scenario: Архивная цель
- **WHEN** цель ARCHIVED содержит нарушения всех условий
- **THEN** для неё не создаётся ни одной проблемы

### Requirement: Отсутствие владельца

Проверка GOAL_NO_OWNER SHALL создавать critical-проблему для активной цели без ответственного.

#### Scenario: Пустой ответственный
- **WHEN** owner_id активной цели равен null, пустой или пробельной строке
- **THEN** создаётся GOAL_NO_OWNER

#### Scenario: Ответственный задан
- **WHEN** owner_id активной цели непустой
- **THEN** GOAL_NO_OWNER не создаётся

### Requirement: Отсутствие КР

Проверка GOAL_NO_KR SHALL создавать critical-проблему для активной цели без КР и не дублировать её нарушением суммы весов.

#### Scenario: Нет ключевых результатов
- **WHEN** активная цель не имеет КР
- **THEN** есть GOAL_NO_KR и нет KR_WEIGHTS_SUM; остальные правила продолжают проверку

#### Scenario: Один КР
- **WHEN** активная цель имеет один КР
- **THEN** GOAL_NO_KR не создаётся

### Requirement: Сумма весов

Проверка KR_WEIGHTS_SUM SHALL создавать major-проблему, если у активной цели есть КР и точная сумма весов не равна 100%.

#### Scenario: Дробная граница
- **WHEN** сумма весов равна 99.99 или 100.01
- **THEN** создаётся KR_WEIGHTS_SUM

#### Scenario: Точная сумма
- **WHEN** веса равны 33.33, 33.33 и 33.34 либо сумма записана как 100.0
- **THEN** KR_WEIGHTS_SUM не создаётся

### Requirement: Каскадирование целей

Проверка CASCADE_NO_PARENT SHALL создавать major-проблему для активной цели некорневого подразделения без активной родительской цели непосредственного вышестоящего подразделения.

#### Scenario: Корень организации
- **WHEN** цель принадлежит корневому подразделению и не имеет родителя
- **THEN** CASCADE_NO_PARENT не создаётся

#### Scenario: Неподходящий родитель
- **WHEN** родитель отсутствует, архивный или находится не в непосредственном родительском подразделении
- **THEN** создаётся CASCADE_NO_PARENT

#### Scenario: Корректный родитель
- **WHEN** родитель активен и находится в непосредственном родительском подразделении
- **THEN** CASCADE_NO_PARENT не создаётся
