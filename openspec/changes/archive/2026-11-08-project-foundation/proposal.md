# Proposal

> Итог 2026-11-08: все задачи выполнены. Ранее перенесённые проверки
> завершены на финальной приёмке (62 теста, два Docker-стенда, HTTP,
> PostgreSQL и полный Liquibase rollback/update). Подробности — docs/verification.md.
> Описания переноса ниже сохраняют историю промежуточных этапов.


## Why

Сейчас есть skeleton, но отсутствуют Docker Compose и подключённый changelog. Нужна воспроизводимая основа, на которой следующий этап сможет создать доменную схему.

## What Changes

- Согласовать существующие Maven Wrapper, Java 21, Spring Boot 3 и настройки приложения без бизнес-классов.
- Добавить Dockerfile, .dockerignore и Compose с приложением, PostgreSQL 15+, healthcheck и отдельным volume.
- Создать пустой корневой changelog, включить Liquibase и проверить подключение к БД.
- Описать окружение и запуск инфраструктуры в начальном README.

## Scope

Только этап 1 — «Инфраструктура приложения». Достаточно текущего skeleton. Старая схема БД не мигрируется: используем отдельную пустую БД и новый volume.
Зависимости реализации: Нет.
Контекст этапа: [01-project-foundation.md](../../../context/stages/01-project-foundation.md).

## Non-goals

- Бизнес-таблицы, JPA-сущности, справочник правил и демонстрационные цели.
- Движок правил, запуск проверок и REST API.
- Новые зависимости, мониторинг и авторизация.

## Capabilities

### New Capabilities

- `project-infrastructure`: Инфраструктура приложения; требования и сценарии этого этапа.

### Modified Capabilities

Нет. На момент планирования основных capability ещё нет; этап вводит собственную границу поведения.

## Impact

Будущие изменения: Dockerfile, .dockerignore, compose.yaml, application.yml, .env.example, db/changelog/changelog.yml, README.md. Существующие зависимости переиспользуются.
Решения, отсутствующие в исходном задании, являются проектными уточнениями и перечислены в design.md.
