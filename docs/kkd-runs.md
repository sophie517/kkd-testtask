# Запуск проверки

`RunService` — внутренний Spring-сервис. Пример вызова из другого Spring-компонента:

```java
RunResult result = runService.start(LocalDate.of(2026, 11, 2), "RUN-002");
```

Дата задаётся явно; previousRunId — ID существующего прогона либо null.
Предыдущий прогон не выбирается по дате. Неизвестный ID вызывает RunNotFoundException;
отсутствующая дата или некорректный формат ID — IllegalArgumentException.
Результат — record с id, status=COMPLETED, snapshotDate, previousRunId и issueCount.
ID нового прогона и проблем генерируются как UUID-строки.

Вызов через Spring bean открывает одну REPEATABLE_READ транзакцию:
1. Проверяет предшественника, читает подразделения, все цели и КР.
2. Проверяет один корень, существование родителей, отсутствие циклов и unit_id целей.
3. Передаёт records движку, сохраняя в контексте архивных родителей.
4. Записывает run, затем run_unit с родителями перед потомками,
   run_goal всех ACTIVE целей (включая корректные), затем issue.
5. Возвращает результат; изменения становятся доступны после успешного commit.

Записи явно flush-ятся в порядке FK. Runtime-ошибки не перехватываются,
поэтому Spring должен откатить транзакцию целиком.
Обход дерева итеративный; некорректная структура отклоняется до записи снимка.
Текущие цели, подразделения и предыдущие снимки не изменяются.

Сервис не вызывается при старте приложения. Два demo-прогона по-прежнему создаются
Liquibase; новый запуск происходит только при явном внутреннем вызове.
POST endpoint, расписание, очередь и состояние RUNNING/FAILED не добавлены.
Не создавайте сервис через new в production: тогда Spring-транзакция не применяется.

## Быстрая проверка

```bash
./mvnw -Dtest=RunServiceTests,KkdServiceApplicationTests test
```

6 тестов сервиса с mock-репозиториями проверяют оба входных fixture,
все активные цели и точные ключи нарушений, порядок подразделений,
некорректные деревья, неизвестного предшественника, распространение ошибки записи
и неизменность ранее созданных объектов снимка после следующего запуска.
Smoke-тест проверяет Spring wiring с mock-репозиториями, без БД и HTTP-сервера.

На финальной приёмке PostgresIntegrationTests проверил настоящий сбой CHECK при
сохранении issue: после выхода из Spring proxy количества run/run_unit/run_goal/issue
не изменились. Успешный запуск сохранил 3 подразделения, 21 цель и 8 проблем.
Временный PostgreSQL trigger подтвердил REPEATABLE_READ внутри транзакции сервиса.
Архивирование текущей цели и переименование подразделения не изменили старую сводку;
удаление тестового прогона каскадно удалило его снимки и проблемы.
